# Manual latency controls and nonnegative settings — same-agent review

Scope: both manual editor layouts and the user's nonnegative-setting rule; reviewed by the implementation agent.

The old rows used long repeated action labels and a wide field, with uneven label/example alignment. ManualDelayField now groups a label above a 112-point right-aligned native input, localized ms unit, short Apply action and explicit example. Full accessible action names, tooltips, identifiers, native editing chrome and the title's initial focus behavior are preserved. An invalid value disables Apply and adds a text/icon explanation.

Review identified three paths where a field-only restriction would be insufficient: direct model/store calls, previously saved signed settings, and a total specification smaller than already-reported hardware latency (which yields a negative additional correction). Domain profile eligibility now checks nonnegative individual and combined values. Model Apply actions and store writes reject unsupported profiles; active store selection excludes them. The raw stored profile remains available for an explicit inactive notice and Reset. Signed data constructors/decoders remain unchanged for old practice snapshots and diagnostic evidence; no schema migration, clamping or historical rerating occurs.

Measured negative candidates retain their values and timelines. Apply is disabled with an explanation; instrument eligibility text is suppressed for these candidates. Per-event signed timing errors remain diagnostic facts, not settings. New manual input and total combined compensation are limited to 0–1000 ms, with decimal dot/comma accepted.
